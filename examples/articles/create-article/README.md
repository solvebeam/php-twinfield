# Create article

> **This example changes data in Twinfield.** It deletes the article again, but only run it on a test administration.

<!-- twinfield-documentation:start -->
Twinfield documentation: [Articles](https://developers.twinfield.com/documentation/api/master-data/articles/).
<!-- twinfield-documentation:end -->

Creates an article with two sub-articles and deletes it again. It uses the code you pass, or else the first unused code from `EXAMPLE999` down (`Example::unusedArticleCode()`). The revenue account and the VAT code are the second and third argument, or else the first profit and loss account and the high sales VAT code of the company.

Describe the article with `ArticleInput`. Every method returns a new input:

| Method | What it sets |
|---|---|
| `ArticleInput::normal($code, $name)`, `::discount()`, `::premium()` | An ordinary article, a deduction or a premium; code (at most 16 characters) and name (at most 40). |
| `shortName()`, `unitNames('Piece', 'Pieces')` | At most 20 characters each; `null` removes them. |
| `vatCode('VH')` | The default VAT code. |
| `percentage()` | The price of a discount or premium is a percentage. |
| `allowChangeVatCode()`, `allowChangeUnitPrice()`, `allowDiscountOrPremium()`, `allowDecimalQuantity()` | What may be changed on the invoice line. Not sent when you do not call them, so Twinfield uses its defaults. |
| `performanceType()`, `allowChangePerformanceType()` | For ICT VAT codes. |
| `subArticle(SubArticleInput)` | Adds a sub-article, or replaces the one with the same code. |

An article needs at least one sub-article, described with `SubArticleInput`:

| Method | What it sets |
|---|---|
| `SubArticleInput::create($name, $generalLedgerAccount, $code)` | Name (at most 80 characters), the revenue account and the code. The code may be left out when the article has one sub-article. |
| `unitPriceExcl('750.00')` or `unitPriceInc('907.50')` | The price excluding or including VAT; setting one clears the other. |
| `units()`, `shortName()`, `costCenter()`, `freeText3()` | Optional. |

Prices are numeric strings or `Amount` objects with at most two decimals, never floats. Invalid input throws an `InvalidArgumentException` before anything is sent.

Twinfield itself has one call for create and update. The SDK makes the difference explicit:

- `create()` reads first and throws an `ArticleAlreadyExistsException` when the code exists, so you never overwrite an article by accident.
- `update()` throws an `ArticleNotFoundException` when the code does not exist (see [Update article price](../update-article-price/)).
- `save()` does what Twinfield does, without the check.

All three read the article back afterwards, so you get the complete `Article`. When Twinfield refuses the article, for example because the VAT code does not exist, you get a `ProcessXmlException` with the message per element.

## Code

```php
$twinfield = Example::twinfield();

$articles = $twinfield->articles();

$article = $articles->create(
    ArticleInput::normal($code, 'Example bike')
        ->shortName('Example bike')
        ->unitNames('Piece', 'Pieces')
        ->vatCode($vatCode)
        ->subArticle(SubArticleInput::create("Example lady's bike", $account, $code . '-L')->unitPriceExcl('750.00'))
        ->subArticle(SubArticleInput::create("Example man's bike", $account, $code . '-M')->unitPriceExcl('760.00')),
);

// Clean up: delete the example article again.
$articles->delete($article->code);
```

## Run

The write guard of the examples blocks changes unless you allow them for a company in `TWINFIELD_WRITE_COMPANIES`:

```sh
TWINFIELD_COMPANY=1002_3 TWINFIELD_ALLOW_WRITES=1002_3 php examples/articles/create-article/example.php
```

`composer test:write` also runs this example, after you confirm the company code.

```text
Created EXAMPLE999 Example bike (VAT code VH)
  EXAMPLE999-L Example lady's bike: 750.00 excl., 907.50 incl.
  EXAMPLE999-M Example man's bike: 760.00 excl., 919.60 incl.
Deleted EXAMPLE999
```
