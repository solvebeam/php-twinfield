# Read article

Reads one article with its sub-articles: the code you pass, or else the first one.

<!-- twinfield-documentation:start -->
Twinfield documentation: [Articles](https://developers.twinfield.com/documentation/api/master-data/articles/).
<!-- twinfield-documentation:end -->

`get()` returns an `Article`; `find()` returns `null` instead of throwing when the code does not exist.

| Property | What it holds |
|---|---|
| `code`, `name`, `shortName` | The article; `shortName` is `null` when not set. |
| `status` | `ArticleStatus`: active, deleted or hidden (deleted while used in an invoice). |
| `type`, `percentage` | `ArticleType::Normal`, `Discount` or `Premium`; a discount or premium is an amount or a percentage. |
| `vatCode` | The default VAT code; `null` when not set, as for a discount. |
| `unitNameSingular`, `unitNamePlural` | The unit, e.g. `Piece` and `Pieces`; `null` when not set. |
| `allowChangeVatCode`, `allowChangeUnitPrice`, `allowDiscountOrPremium`, `allowDecimalQuantity` | What may be changed on the invoice line. |
| `performanceType`, `allowChangePerformanceType` | For ICT VAT codes; `null` when not set. Twinfield leaves them out for discounts and premiums. |
| `subArticles` | The `SubArticle`s, deleted ones included; `activeSubArticles()` leaves those out, `subArticle($code)` gives one. |

A `SubArticle` has the price and where the revenue goes:

| Property | What it holds |
|---|---|
| `code` | The code for the invoice line; `null` for the only sub-article of an article, which may have no code. |
| `name`, `shortName`, `units` | Name, and the number of units of the article per quantity. |
| `unitPriceExcl`, `unitPriceInc` | Price excluding and including VAT; for a discount or premium with a percentage, the percentage. |
| `generalLedgerAccount`, `generalLedgerAccountName` | The revenue account. |
| `costCenter`, `costCenterName`, `freeText3` | `null` when not set. |
| `status`, `inUse` | `SubArticleStatus` (active or deleted), and whether an invoice uses it. |

Prices are `Amount` objects: numeric strings with two decimals (`'750.00'`), never floats.

`subArticles($articleCode)` on the resource gives only the code and name of the sub-articles, with the Finder type `SAR`: one small request, e.g. to fill a list.

When Twinfield returns something the SDK does not expect, such as an unknown article type, you get an `UnexpectedResponseException` with the path of the element, instead of a silent default.

## Code

```php
$twinfield = Example::twinfield();

try {
    $article = $twinfield->articles()->get($code);
} catch (ArticleNotFoundException $exception) {
    echo 'Not found: ', $exception->reason, PHP_EOL;

    exit(1);
}

foreach ($article->subArticles as $subArticle) {
    echo 'Sub:       ', $subArticle->code ?? '(no code)', ' ', $subArticle->name, ': ';
    echo $subArticle->unitPriceExcl, ' excl., ', $subArticle->unitPriceInc, ' incl., ';
    echo 'account ', $subArticle->generalLedgerAccount, ', ', $subArticle->status->value;
    echo $subArticle->inUse ? ' (in use)' : '', PHP_EOL;
}
```

```sh
php examples/articles/read-article/example.php
php examples/articles/read-article/example.php BIKE
```
