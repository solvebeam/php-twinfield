# Delete article

> **This example changes data in Twinfield.** It creates an article first, but only run it on a test administration.

<!-- twinfield-documentation:start -->
Twinfield documentation: [Articles](https://developers.twinfield.com/documentation/api/master-data/articles/).
<!-- twinfield-documentation:end -->

Creates an example article, deletes it, activates it and deletes it again.

`delete()` returns a `DeleteResult`:

- `DeleteResult::Deleted`: the article is deleted.
- `DeleteResult::Hidden`: an invoice uses the article, so Twinfield hid it instead.

`activate()` makes a deleted or hidden article active again. Both read the article first and throw an `ArticleNotFoundException` when the code does not exist: an `<article>` request for an unknown code would create it.

## Code

```php
$twinfield = Example::twinfield();

$articles = $twinfield->articles();

$result = $articles->delete($code);

echo $result === DeleteResult::Deleted ? 'Deleted ' : 'Hidden ', $code, ': status ';
echo $articles->get($code)->status->value, PHP_EOL;

// A deleted or hidden article can be activated again.
$articles->activate($code);
```

## Run

The write guard of the examples blocks changes unless you allow them for a company in `TWINFIELD_WRITE_COMPANIES`:

```sh
TWINFIELD_COMPANY=1002_3 TWINFIELD_ALLOW_WRITES=1002_3 php examples/articles/delete-article/example.php
```

`composer test:write` also runs this example, after you confirm the company code.

```text
Created EXAMPLE999
Deleted EXAMPLE999: status deleted
Activated EXAMPLE999: status active
Deleted EXAMPLE999
```
