A browse code is a predefined set of fields that Twinfield gives data for, see [Browse data](/guides/browse-data/). This page lists all browse codes of the [Twinfield documentation](https://developers.twinfield.com/documentation/api/request-data/browse-data/), each with an example, the request and response XML, and the browse definition: all fields of the code and which of them can be a criterion.

The code links to the example, the number of fields to the browse definition in [`browse-definitions/`](https://github.com/solvebeam/twinfield-php/tree/main/browse-definitions). The names are in the language of the user who reads the definition. `browse()` also takes a string, e.g. `browse('030_3')`, so a code Twinfield adds later works without an SDK update.

Keep in mind:

- **Twinfield does not apply the proposed criteria of the definition.** Send every criterion you need, such as the status.
- **Some criteria are required.** 400 and 410 give a server error without `fin.trs.head.bankcode` (the cash or bank book); in 040_1, 050_1 and 060 Twinfield uses the `Generic` regime when you leave it out.
- **A field with `visible` false is a criterion only**, e.g. `fin.trs.head.yearperiod` in 030_3. Asking for it as column can give a server error.
- **Totals have no transaction line.** 040_1, 050_1, 060, 620 and 670 group and sum the lines, so `$row->transactionLine` is null. The rows of 680, 680_2 and 700 are not transaction lines either.
